## 권한 기준

15번 마이그레이션이 ROLE_DESIGN.md의 14번 담당 파트 제한에 동급 열람을 추가합니다. 동급은 작성 당시 직급을 기준으로 하며 기능 관리자 자체는 사역 직급이 아닙니다. 담당 파트·최상단의 기존 권한도 유지합니다. 동급 열람만으로 수정·검토·공개 권한을 얻지 않습니다.

기도제목·비공개 글·아이들 명단과 보호자 연락처는 동급 열람에 포함하지 않습니다. 담당 교역자와 최상단의 기존 제한 및 개별 공개 규칙을 따릅니다. 실제 계정의 역할과 담당 파트는 아직 배정하지 않았습니다.

리허설은 미기록을 결석으로 계산하지 않습니다. 미참석 정렬은 결석과 사유 결석을 합산하며 사유 결석도 따로 표시합니다. 같은 회차·사람을 다시 저장하면 기존 기록을 갱신합니다. 회의·공과는 아이들 출결 통계에서 제외합니다.

등록신청 푸시에는 개인정보를 넣지 않습니다. 활성화되고 알림 수신을 설정한 관리자·최상단 구독에 전송합니다. 테스트용 실제 신청이나 푸시 발송은 하지 않았습니다.

## 운영 적용 전

운영은 a480e73, DB는 12번입니다. 새 앱은 13→14→15번 마이그레이션이 필요합니다. 별도 운영 DB 승인 후 원본 보존·권한 확인을 거쳐 앱을 배포해야 합니다. 14번은 기존 JSON의 작성자 이름·담당 파트부터 보존하며 15번은 동급 열람, 리허설, 등록신청 큐를 추가합니다. public 스키마와 auth 트리거는 변경하지 않습니다.

로컬 검증: DB 테스트 80개, lint, tsc --noEmit, build --webpack 통과. node_modules junction의 경계 때문에 로컬에서는 webpack으로 빌드했습니다. 실제 계정별 새 화면과 운영 푸시 수신은 미확인입니다.

# TLC 예배 PD 체크리스트 — 웹앱 설계서

- 버전: v1 (2026-11-06)
- 함께 전달하는 파일
  - `tlc-pd-checklist-data.json` — 주일 1부 체크리스트 전체 내용 (이 설계서의 데이터 구조를 따름)
  - `reference-prototype.html` — 현재 동작하는 프로토타입 (화면·인쇄 디자인 기준). 브라우저로 열어 확인 가능

---

## 1. 목적

주님의교회(TLC)는 예배마다 **예배 PD**를 둡니다. PD는 특정 팀 업무를 대신하지 않고, 예배가 정시에 시작되고 어느 순서에서도 공백이 생기지 않도록 전체를 확인하고 지휘합니다.

이 앱은 PD가 다음 일을 하도록 돕습니다.

1. 예배 전: 시간 순서(T-60 → START)대로 체크
2. 예배 중: 현재 순서를 보며 다음 순서 준비 (FLOW + "이때 준비")
3. 예배 후: 종료 체크와 PD REPORT 작성, 다음 예배 PD에게 인수인계
4. 체크리스트를 **A4 가로 2페이지**로 인쇄 (코팅용 빈 양식 / 그날 작성본)
5. 관리자가 체크리스트 내용을 **앱 안에서 직접 수정**하고, 수정 내용이 모든 PD에게 공유됨

---

## 2. 사용자와 권한

| 역할 | 할 수 있는 것 |
|---|---|
| 관리자 (DH) | 모든 예배의 템플릿 편집, 항목 추가·삭제·순서 변경, 예배 추가, 기록 열람 |
| PD | 자기 예배 회차(날짜 × 예배)에 체크, 담당자 기재, 조건 토글, PD REPORT 작성, 인쇄 |
| 열람자 (선택) | 기록·리포트 보기만 |

- 예배마다 PD가 다르다 (1부 PD ≠ 2부 PD).
- 템플릿 편집 권한은 관리자만. PD는 그날 회차의 내용만 작성.

---

## 3. 핵심 개념: 템플릿과 회차

두 종류의 데이터를 분리합니다.

| 구분 | 설명 | 저장 단위 | 누가 바꾸나 |
|---|---|---|---|
| **템플릿 (Template)** | 예배별 체크리스트 내용 — 블록, 항목, FLOW, 담당자 칸, 리포트 항목 | 예배 1개당 1개 (주일 1부, 2부, 3부, 라이프라인) | 관리자 (편집 모드) |
| **회차 (Run)** | 특정 날짜의 특정 예배 기록 — 체크 상태, 담당자 이름, 조건, 리포트 | 날짜 × 예배 (예: 2026-11-08 주일 1부) | 그날 PD |

- 회차는 생성 시점의 템플릿을 참조합니다. 템플릿이 나중에 바뀌어도 지난 회차 기록은 깨지지 않도록 **회차 생성 시 템플릿 스냅샷(또는 버전 번호)을 함께 저장**합니다.
- 공유 저장소(서버 DB)에 저장. 같은 회차를 여러 기기에서 열어도 같은 내용이 보여야 함.

## 4. 화면 구성

### 4-1. 상단 바 (항상 표시, 인쇄 시 숨김)

- 예배 선택: 주일 1부 / 2부 / 3부 / 라이프라인
- 날짜 (기본값: 다가오는 주일, 라이프라인 포함 모두 주일 기준)
- PD 이름
- 조건 토글 3개: 성찬주간(1주차) · 영상소식 있음 · 변경사항 있음
- 진행률: 막대 + `체크한 수 / 해당 항목 수`
- 인쇄 형식: 작성본 / 빈 양식 + 인쇄 버튼
- 체크 초기화 / 전체 초기화 (두 번 눌러야 실행되는 확인 방식)
- 편집 모드 버튼 (관리자만)

### 4-2. 1페이지 — 예배 시작 전

- 머리: `TLC 예배 PD Checklist` / `예배 시작 전` / 날짜·PD 기재란 / `주일 1부 08:20`
- **시간 블록**이 왼쪽 → 오른쪽으로 흐름. 2줄 구성
  - 1줄: T-60 · T-45 · T-30 · 부산 ATEM(1부·라이프라인) 또는 인수인계(2·3부)
  - 2줄: T-10 · T-5 · T-2 · T-1 · START
- 블록 구성 요소
  - 머리: **실제 시각**(크게) + 구분 표시(T-60 등) + 제목
  - 도착 표시: 그 시간에 도착·시작하는 팀 (예: `07:30 영상·사진·조명팀 기도 @중계실`)
  - 체크 항목, 소제목, 체크 그룹(타일), 기준 메모, 위치별 송출표

### 4-3. 2페이지 — 예배 진행 · 종료

- 배너: "현재 순서를 보면서 다음 순서를 준비합니다"
- **FLOW** 3줄 표
  - 1줄: 순서 칸 (COUNTDOWN → … → MP3 전환)
  - 2줄: "이때 준비" — 그 순서가 진행되는 동안 준비할 것
  - 3줄: 체크칸
- **오늘 담당자** 기재란 (순서 담당 / 예배위원 / 예배팀 / 기술팀)
- 하단 3열: 예배 진행 중 · 예배 종료 후 · PD REPORT

### 4-4. 반응형

- 데스크톱: 위 배치 그대로
- 태블릿: 블록 2열
- 휴대폰(약 400px): 블록 1열, FLOW는 가로 스크롤, 상단 바는 고정 해제
- 페이지 전체가 가로로 스크롤되면 안 됨

## 5. 기능 상세

### 5-1. 체크

- 항목 클릭/탭으로 체크·해제. 체크된 항목은 흐리게 + 취소선
- 체크 즉시 회차에 저장 (공유)
- 진행률은 **현재 조건에 해당하는 항목만** 계산. PD REPORT 항목은 진행률에서 제외

### 5-2. 조건 (해당 시에만 표시되는 항목)

| 조건 ID | 토글 이름 | 항목 태그 | 기본값 |
|---|---|---|---|
| `communion` | 성찬주간 (1주차) | 성찬주간 | 날짜가 1~7일이면 자동으로 켜짐, 수동 변경 가능 |
| `news` | 영상소식 있음 | 영상소식 있을 때 | 켜짐 |
| `changes` | 변경사항 있음 | 변경 시 | 꺼짐 |

- 조건이 붙은 항목은 주황 태그로 표시
- 조건이 꺼지면: 화면에서는 흐리게 + 취소선(구조는 보이게), 진행률에서 제외, 작성본 인쇄에서는 숨김
- FLOW에서 조건이 꺼진 순서 칸(성찬, 영상소식)은 화면·작성본에서 빠짐
- 찬양과 경배 시간 표시: 기본 `20분`, 성찬주간이면 `15분` (`subWhen`)

### 5-3. 담당자 기재

- 칸별 텍스트 입력. 여러 명 칸(헌금위원, 안내위원, 예배팀)은 쉼표로 구분
- 예배별로 칸 구성이 다름 (예: 라이프라인만 "강대상 옮김")
- 칸 구성은 템플릿에서 편집

### 5-4. PD REPORT

- 문제 분류 체크 7개
- 문제 유무(없음/있음), 내용, 현장 처리, 추가 조치(불필요/필요), 담당자, 다음 예배 전
- (확장) 저장된 리포트를 날짜별로 모아 보는 목록 화면

### 5-5. 편집 모드 (관리자)

편집 모드를 켜면 같은 화면에서 바로 수정합니다 (별도 관리자 화면보다 우선).

- **항목**: 문구 수정(그 자리 편집), 추가, 삭제, 위아래 이동(드래그 또는 ▲▼)
- **항목 속성**: 강조(굵게/점 강조), 팀 태그(음향·영상·자막·사진·조명·부산 중 선택), 조건(없음/성찬주간/영상소식/변경 시)
- **블록**: 시각(분 단위 offset), 구분 표시, 제목, 스타일(기본/부산 강조/큐/START), 도착 표시 추가·수정·삭제, 블록 추가·삭제·순서 변경
- **FLOW**: 순서 칸 추가·삭제·이동, 이름, 보조 문구, 스타일, 조건, 플래그(예: 공조 OFF), "이때 준비" 문구
- **담당자 칸**: 그룹·칸 추가·삭제, 칸 이름, 넓이(1/3/6칸)
- **예배 복제**: "1부를 복사해서 2부 만들기" → 시작 시각만 바꾸면 모든 시각이 자동 재계산 (5-6 참고)
- 저장 시 템플릿 버전 +1, 수정자·시각 기록
- 실수 방지: 저장 전 취소 가능, 직전 버전으로 되돌리기

### 5-6. 시간 계산 규칙

- 블록·도착 표시·FLOW의 시각은 **예배 시작 기준 분(offsetMin)**으로 저장
  - 예: 주일 1부 시작 08:20, T-60 블록 `offsetMin: -60` → 07:20
  - 부산 ATEM 블록 `offsetMin: -20` → 08:00
- 화면에 보이는 시각 = 시작 시각 + offsetMin
- 시작 시각을 바꾸거나 예배를 복제하면 모든 시각이 자동으로 맞춰짐
- 단, 2·3부처럼 집결 시간이 일정한 간격이 아닌 경우 도착 표시의 offsetMin을 직접 조정

### 5-7. 인쇄

- 용지: **A4 가로, 정확히 2페이지** (1페이지 = 예배 시작 전, 2페이지 = 예배 진행·종료)
- 여백 7mm × 8mm, 배경색 인쇄 (`print-color-adjust: exact`)
- 상단 바·편집 도구 숨김
- **작성본**: 입력한 날짜·PD·담당자·리포트·체크 표시 출력, 조건이 꺼진 항목은 숨김
- **빈 양식 (코팅용)**: 모든 조건 항목 표시(태그 포함), 체크·입력값 비움, 기재란은 밑줄만
- 내용이 늘어 2페이지를 넘을 때: 편집 모드에서 경고 표시 ("인쇄 시 2페이지 초과")
- PDF 저장 버튼이 있으면 좋음 (브라우저 인쇄 대화상자 대안)

## 6. 데이터 구조 (`tlc-pd-checklist-data.json`)

### 6-1. 최상위

```json
{
  "schemaVersion": 1,
  "conditions": [ { "id": "communion", "label": "...", "tag": "...", "default": false } ],
  "teams": ["음향", "영상", "자막", "사진", "조명", "부산"],
  "services": [ Service ]
}
```

### 6-2. Service (= 템플릿)

```json
{
  "id": "sun1",
  "name": "주일 1부",
  "start": "08:20",
  "flowType": "sunday",
  "handoverTo": "2부 PD",
  "page1": { "title": "예배 시작 전", "rows": [ [Block], [Block] ] },
  "page2": {
    "title": "예배 진행 · 종료",
    "banner": "...",
    "flow": [ FlowStep ],
    "roster": [ RosterGroup ],
    "during": { "title": "예배 진행 중", "items": [ Item ] },
    "after":  { "title": "예배 종료 후", "items": [ Item ] },
    "report": { "categories": [ {id, text} ], "fields": [ ReportField ] }
  }
}
```

### 6-3. Block

```json
{
  "id": "blk_0720",
  "offsetMin": -60,
  "label": "T-60",
  "title": "전체 상황",
  "style": "default | accent | cue | go",
  "arrivals": [ { "offsetMin": -60, "text": "예배팀 · 음향팀 기도", "place": "대예배실" } ],
  "items": [ Item ]
}
```

- `style`: `default` 흰 카드 / `accent` 부산 ATEM(연한 파랑) / `cue` T-2·T-1(파란 테두리) / `go` START(남색 카드)

### 6-4. Item (type별)

| type | 필드 | 설명 |
|---|---|---|
| `check` | `id`, `text`, `emphasis?`(`strong`/`highlight`), `teams?`, `condition?` | 기본 체크 항목. `highlight`는 점 강조 (공조 ON/OFF 등) |
| `heading` | `text` | 블록 안 소제목 |
| `checkGroup` | `layout`(`columns`/`auto`), `columns?`, `items[{id,text}]` | 타일형 체크 묶음. `auto`는 글자 길이에 맞춰 줄바꿈 |
| `note` | `parts[{text,bold}]` | 기준 메모 (예: "파일 있음 ✕ → 최종본 + 실제 재생") |
| `locationMatrix` | `columns[{key,label}]`, `rows[{id,label}]` | 위치 × 영상/음향 체크표. 체크 ID = `row.id + column.key` |

- 모든 체크 ID는 템플릿 안에서 고유. 회차 기록은 이 ID로 체크 상태를 저장하므로 **문구를 바꿔도 ID는 유지**

### 6-5. FlowStep

```json
{ "id": "s4", "label": "찬양과 경배", "style": "default", "sub": "20분",
  "subWhen": { "communion": "15분" }, "condition": null, "flag": null, "next": "마지막 곡 → 영상소식 전환 준비" }
```

- `style`: `countdown` · `liveStart` · `start` · `default` · `optional`(성찬처럼 조건부, 점선) · `liveEnd` · `end`(MP3 전환)
- `offsetMin`이 있으면 보조 문구 대신 실제 시각 표시 (COUNTDOWN 08:18 등)
- `flag`: 칸 안 주황 표시 (예: 헌금 `공조 OFF`)

### 6-6. RosterGroup / ReportField

```json
{ "group": "예배위원", "sub": "", "fields": [ { "id": "r7", "label": "헌금위원", "span": 3, "multiple": true } ] }
{ "id": "w3", "label": "내용", "type": "text | choice", "options": ["없음","있음"], "placeholder": "..." }
```

### 6-7. Run (회차 기록 — 앱에서 새로 저장)

```json
{
  "serviceId": "sun1",
  "date": "2026-11-08",
  "templateVersion": 3,
  "pd": "홍길동",
  "conditions": { "communion": false, "news": true, "changes": false },
  "checks": { "a1": true, "d5v": true },
  "roster": { "r1": "...", "r7": "김OO, 이OO" },
  "report": { "w_issue": "있음", "w3": "...", "categories": ["q1"] },
  "updatedAt": "2026-11-08T08:25:00+09:00",
  "updatedBy": "..."
}
```

## 7. 디자인 기준

방향: 절제되고 깔끔한 큐시트. 흰 카드 위에 **시각이 가장 먼저** 보이고, 색 강조는 T-2·T-1·START·부산 ATEM에만.

| 토큰 | 값 | 용도 |
|---|---|---|
| bg | `#f2f4f7` | 화면 배경 (인쇄 시 흰색) |
| paper | `#ffffff` | 카드 |
| ink | `#172235` | 본문 |
| muted | `#677386` | 보조 문구 |
| line | `#e2e7ee` | 구분선 |
| soft | `#f6f8fb` | 도착 표시·타일 배경 |
| accent | `#2b62c4` | T-2·T-1, 팀 태그, 시각 강조 |
| accent-soft | `#eaf0fb` | 부산 카드, 태그 배경 |
| navy | `#15284a` | START 카드, 배너, 주요 버튼 |
| amber | `#a85a17` / `#fbf0e3` | 조건 태그, 공조 OFF 플래그 |

- 글꼴: 본문 IBM Plex Sans KR, 숫자·시각 IBM Plex Sans (tabular-nums). 대체 글꼴 Malgun Gothic
- 카드 모서리 14px (인쇄 2.6mm), 체크박스 18px 둥근 사각
- 다크 모드 지원 (프로토타입 CSS 참고), 인쇄는 항상 밝은 색
- 교회 웹앱 공통 색(#20365B, #4E6285)에 맞출지는 결정 필요 — 맞춘다면 navy·accent만 교체

## 9. 완료 기준

- [ ] 주일 1부 화면이 `reference-prototype.html`과 같은 내용·순서로 표시된다
- [ ] JSON을 불러와 화면이 그려진다 (내용이 코드에 하드코딩되지 않음)
- [ ] 체크·담당자·조건·리포트가 공유 저장되어 다른 기기에서 같은 회차를 열면 동일하게 보인다
- [ ] 성찬주간 토글 시 성찬 항목·FLOW 칸·찬양 15분 표시가 바뀐다
- [ ] 진행률이 해당 항목만 센다

- [ ] 1부를 복제해 시작 시각을 바꾸면 모든 시각이 자동 계산된다
- [ ] 작성본·빈 양식 모두 A4 가로 정확히 2페이지로 인쇄된다
